# Contributing

Contributions must remain fictional, vendor-neutral, and suitable for unrestricted public release.

1. Identify the affected mission outcome, workload archetype, architecture decision, migration wave, verification activity, and operational owner.
2. Update traceability, diagrams, templates, and decision records together.
3. Use only reserved example domains and synthetic identifiers.
4. Never include credentials, real account numbers, operational network ranges, or third-party work product.
5. Add a new ADR when changing an isolation boundary, identity model, network pattern, data authority, migration strategy, recovery design, or governance responsibility.
